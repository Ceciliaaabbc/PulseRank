# 阶段0：脚手架 + 核心链路打通

## 目标

跑通最小业务闭环：提交一条评分 → 写入 MySQL → 实时查询某商品的聚合平均分。这是后续所有稳定性优化（缓存、削峰、限流熔断、JVM调优）的性能基线，本阶段本身不引入任何优化手段。

## 做了什么

**技术栈**：Java 21 + Spring Boot 3.5.7 + Maven + MySQL 8（Docker Compose 本地起）。

**数据模型**：单张 `rating` 表（`product_id`、`user_id`、`score`、`created_at`），没有做任何预计算字段或汇总表。

**API**：
- `POST /api/ratings` —— 提交评分，`score` 用 Bean Validation 限制在 1-5
- `GET /api/products/{productId}/score` —— 实时执行 `SELECT AVG(score), COUNT(*) FROM rating WHERE product_id = ?` 返回聚合结果，商品没有评分时返回 `avgScore=0, ratingCount=0` 而不是报错

**Docker Compose**：目前只起了 MySQL 一个服务。

## 为什么这样做

**聚合查询故意做成"每次都实时查库"，不做预计算/缓存**：这是阶段0 最关键的设计决定。因为阶段1 要引入 Redis 多级缓存，衡量效果需要一个"无缓存"基线——如果现在就顺手加缓存或者用一个汇总字段维护计数，阶段1 就没有干净的 before/after 对比数据了。基线越朴素，后面每一步优化的效果才越有说服力。

**Docker Compose 只起 MySQL，Redis 和 Kafka 都还没加**：即使 Kafka 是本项目确定要用的中间件，阶段0 也不需要它——异步削峰是阶段2 的验证点，现在加进来只是让 docker-compose 和依赖变复杂，却没有代码用到它，不符合"每阶段只做当前阶段要验证的事"的原则。Redis 同理，留给阶段1。

**放弃 Lombok，手写 getter/setter**：最初打算用 Lombok 减少样板代码，但在本机 JDK 23 + Maven 3.9.9 的组合下，Lombok 1.18.42 的注解处理没有生效——生成的 getter/setter/全参构造方法在编译期完全找不到符号，报错分布也比较误导人（javac 对"参数本身就是错误类型"的调用链会抑制级联报错，一开始看着像是只有部分类受影响，实际是整个注解处理都没跑起来）。排查这类工具链兼容性问题的时间成本，对阶段0 这种基础脚手架来说不划算，直接手写四个类的样板代码更稳，也少了一个"换机器/换JDK版本编译不过"的风险点。后续如果需要减少样板代码，可以再单独排查或换用 Java record（DTO 部分很适合用 record，实体类因为 JPA 懒加载代理的原因不太适合）。

**JDBC URL 加了 `allowPublicKeyRetrieval=true`**：MySQL 8 默认认证插件是 `caching_sha2_password`，mysql-connector-j 在未加密连接下首次认证需要向服务端请求 RSA 公钥，默认被驱动拒绝（`Public Key Retrieval is not allowed`）。本地开发库、非公网暴露，这个参数是安全的；生产环境应该用 TLS 连接而不是开这个开关。

**本地端口用了 8081 而不是默认的 8080**：本机 8080 已经被另一个项目（`FullStack_Framework`）占用，不能确定那是不是用户正在跑的其他项目，没有贸然去关它，直接把 PulseRank 改到 8081。

## 验证方式

本地 `docker compose up -d` 起 MySQL，等健康检查通过后 `mvn clean package` + `java -jar` 启动应用，用 curl 端到端测试：

```
POST /api/ratings {productId:1001, userId:1, score:5} → 201 记录写入成功
POST /api/ratings {productId:1001, userId:2, score:3} → 记录写入成功
GET  /api/products/1001/score → {avgScore: 4.0, ratingCount: 2}   ✓ 聚合正确
GET  /api/products/9999/score → {avgScore: 0.0, ratingCount: 0}   ✓ 无评分时不报错
POST /api/ratings {..., score:6} → HTTP 400                        ✓ 参数校验生效
```

全部符合预期，Hibernate 自动建表（`ddl-auto: update`）也验证通过。
